# 醫聖 REGISTER 狀態與日期（匯入／清單用）

權威實作：`src/core/yisheng_register_fields.py`  
現金帳人數：`src/infrastructure/sqlite_shadow_store.py` 的 `cash_book_summary`，以及掛號存檔時寫入的 `reg_cc`／`reg_remark`。  
欄位對照來源：`REGIBRW.Dat` 的 `BDATA`（醫聖掛號瀏覽定義）。現金帳初診／欠卡的判斷對過 `Sc.exe` 的掛號簿計數。

## 日期（先前用錯的根因）

| 醫聖欄位 | REGIBRW 顯示 | 我們的用法 |
|----------|--------------|------------|
| **`R_DATE`** | **看診日** | **清單分日、`encounter_date`、年齡 as-of** |
| `O_DATE` | （不當作看診日） | Encounter id 穩定鍵一部分；副存 `opdDate` |

**序號 `SERNO` 在同一 `R_DATE`＋時段（`SLOT`）下唯一。**  
若誤用 `O_DATE` 分日，會把不同看診日、碰巧同序號的人擠在同一天 → 看起來像幽靈重號。

年齡公式對齊：`TwAgeDate(Birthday, Main->R_date)` → 用看診日算歲.月。

## 狀態標記

| 標記 | 含義 | 處理 |
|------|------|------|
| DBF `*`（0x2A） | 檔案層刪除 | 讀檔跳過 |
| `REGIDELE.Dat` | 刪掛／取消預約歸檔 | 不當有效就診 |
| `STATUS=0`＋收據 0＋沒有真的診斷 | 未批價刪掛殘留 | `cancelled`，不進現金帳 |
| 診斷 `!` 開頭且收據 0，但不是 `!07Y` | 未批價刪掛殘留 | 同上，不進現金帳 |
| 診斷 `!07Y`（收據可以是 0） | 自費診斷代碼，人要留在現金帳 | 當有效就診。費用維持原值（這批是 0） |
| 有寫診斷、或已經有收據 | 有效就診 | 留在現金帳。`STATUS=0` 但診斷是真的，也算 |
| `STATUS=A`（多為 `FORESPEAK=預`） | 預掛未報到 | 掛在 **`R_DATE`** 當日，`waiting`＋預 |
| `STATUS=-` / `+` | 有效完診 | 掛在 **`R_DATE`**，進清單 |

## 序號欄

`Trans(Main->SerNo,"@Z 999")` → 就是 `SERNO`，沒有用錯欄。

## 現金帳人數怎麼算

這些標記都有用，不是多餘欄位。掛號簿的初診、複診、欠卡就是靠它們。

| 欄 | 規則 |
|----|------|
| 身分 | 案件是「自」或「自費」，或負擔代碼空白／`0` → 自費。否則用負擔代碼。沒有「0」這一列 |
| 初診 | `CC` 共 6 碼，**第 4 碼是 `$`**。不是「序號等於 1」，也不是「字串裡隨便有一個 `$`」 |
| 複診 | 有效就診，但第 4 碼不是 `$`（常見是 `#`，或空白） |
| 欠卡 | 押金 `fee_deposit` > 0，**或** 備註正好是「押」 |
| 還卡 | `cash_return`。還卡不加一個人，也不改應收的算法 |
| 應收 | 不因補人數而改金額 |

`CC` 其他位置的 `!`、`*` 不決定初診或複診。第 4 碼仍是 `$` 就還是初診，是空白或 `#` 就是複診。匯入時原樣保留，新病歷不另外發明這兩個符號。

## 歷年 `!07Y` 有沒有漏

2026-10-15 把 `REGISTER.Dat` 全部年份掃過，不是只看今年。

- 收據為 0、診斷 `!07Y` 的就診，**只有 2026 年 23 筆**。2015–2025 沒有這個寫法。這 23 筆都已經在影子庫，費用合計沒有變。
- 其中 19 筆 `CC` 尾端是 `!`，4 筆是 `*!`。第 4 碼都是空白，所以算複診。
- 2018 另有 1 筆 `!07Y` 是有收據的，原本就留在現金帳。
- 其他年份那些 `!` 開頭、收據 0 的診斷（例如 `!00>`）仍是刪掛殘留，不補進來。補進來會把已對上的金額和人數打亂。
- 2009–2025 每一筆「不算刪掛」的掛號，影子庫都已經有。`reg_cc` 沒有空白未回填的列。
- 2026-10-15 有 12 筆、2026-10-18 有 1 筆預掛，還沒從醫聖補進影子庫。那是上次匯入之後的看診日，不是這次 `!07Y` 的洞。這次沒有把他們匯進來。

九月人數仍是 2,165：003 初 1 複 7、004 初 2 複 19、902 初 8 複 4、D12 初 353 複 1621 欠 22、D24 初 11 複 114 欠 3、自費初 5 複 20 欠 6。四月自費仍是初 4、複 18、欠 0。

## 北極星自己掛號、存檔

建檔走 `cache_resource`。每一次把 Encounter 寫進影子庫（掛號、改掛、退押金）都會配對現金帳標記。只改報表、不寫欄位是不夠的。

| 情況 | 寫入 |
|------|------|
| 這筆還沒有 `CC`，而且沒有更早的有效就診 | `CC` = `   $  `（第 4 碼 `$`，初診） |
| 這筆還沒有 `CC`，但已有更早的有效就診 | `CC` = `   #  `（第 4 碼 `#`，複診） |
| 醫聖匯入的 `CC` 已經有值（含空白、`!`、`*`） | 不覆寫 |
| 這次存檔押金 > 0，而且備註是空的 | 備註寫「押」。欠卡同時也認押金金額 |
| 這次存檔把押金改成 0，原本有押金，備註是「押」 | 清掉「押」。人離開欠卡。還卡仍記在 `cash_return` |
| 舊資料是「押」但押金已經是 0 | 保留。那是醫聖留下的欠卡，不是這次退押 |

`CC` 存在掛號擴充的 `regCc`，而且保留空白，避免第 4 碼被剪掉。備註存在 `noteMark`，索引欄是 `reg_remark`。

用拋棄的空資料庫試過：第一筆第 4 碼是 `$`、押金 500 時備註為「押」；退押後押金 0、備註清掉、第 4 碼仍是 `$`。第二筆第 4 碼是 `#`。已寫好的 `   # !` 再存一次不會被蓋掉。
