# 主機與工作站



病歷只在**主機**。其他電腦用瀏覽器連主機，自己只負責本機列印。不要在工作站再雙擊「啟動門診」，否則會變成另一套空資料庫。



## 主機



1. 第一次：雙擊 `安裝-主機必要工具.bat`（會用 winget 補 Python、Node，建立 `.venv`，並在登入時自動把服務藏到背景）。

2. 平常：雙擊 `啟動-Wundadi門診.bat`。API `0.0.0.0:5000`、畫面 `0.0.0.0:3010`，記錄在 `data/logs/`，沒有命令視窗可關。

3. 改過程式要吃進去：雙擊 `重啟全部-Wundadi門診.bat`。

4. 其他電腦把 `客戶端` 資料夾放到一個固定位置，雙擊裡面的 `開啟門診.exe`，會自己找到這台。防火牆規則名稱是 `PSEHR-3010`、`PSEHR-5000`、`PSEHR-5301`（網域和私用網路）。沒有系統管理員權限時規則可能加不上，要手動允許這三個連接埠。



## 工作站

把整個 `客戶端` 資料夾放到那台電腦的一個固定路徑（不要拷整份程式、不要拷病歷）。資料夾裡有 `開啟門診.exe`，旁邊是免安裝的 `SumatraPDF.exe`。

1. 雙擊 `開啟門診.exe`。桌面會出現同名捷徑，以後用捷徑即可。登入後工具會自己跑。
   同一資料夾的 `環境檢查.exe` 開一個視窗，看這台的 Edge、PDF、.NET 6、讀卡 6.0、印表機、VPN、主機。缺讀卡環境時，視窗裡可以直接裝資料夾裡帶的檔。
2. 工具把這台的印表機、讀卡軟體、PDF、VPN 回報給診所網站。工作站必須用「開啟門診.exe」開啟才能讀這台的卡。用 Chrome 或直接開網址，讀不到這台插的卡。
3. 資料夾裡的「讀卡6.0」有讀卡軟體 6.0，以及安裝時會要的 .NET Runtime 6 與 ASP.NET Core Runtime 6（都是 32 位元）。新的一台雙擊該資料夾的「安裝讀卡.bat」。健保 VPN 不在資料夾裡，也不會代登。PDF 工具是免安裝版，跟執行檔放在一起。
4. 不要在工作站跑主機的啟動檔。資料夾可以整包搬走；搬走之後再雙擊一次執行檔，捷徑會改指新位置。


## 大廳紅燈



點紅燈會做能自動做的事：



| 燈 | 點了之後 |

|----|----------|

| 讀卡機 | 主機上若已安裝 6.0，就啟動或重啟主控台 |

| PDF 未裝 | 工作站資料夾裡的免安裝 SumatraPDF.exe 不在。放回「開啟門診」旁邊即可 |

| PDF 未起 | 這台還沒有回報。雙擊工作站資料夾裡的「開啟門診」 |

| 印表機 | 只說明離線，不會假裝修好硬體 |

| VPN | 只提醒人工登入。系統不代登健保 VPN |

| 資料 | 顯示後端連不上。主機服務沒開就回主機雙擊啟動 |



## 讀卡軟體 6.0 與診所金鑰



乾淨電腦的正確起點不是把工具塞進 GitHub。



- **程式本體**放 GitHub（公開 repo `PSEHR`）。病歷庫 `data/`、費用統計範例、讀卡安裝檔、SAM／金鑰都不要推上去。

- **Python、Node** 是一般軟體，主機安裝腳本會用 winget 補，不必把安裝檔提交進 repo。**SumatraPDF** 用官方免安裝版，放在本機的 `客戶端` 資料夾跟著拷走，不推上 GitHub。

- **健保讀卡軟體 6.0** 裝在每一台會插卡掛號的電腦，不只主機。用健保專網下載。沒裝時紅燈會說明，程式不會自己從不明網址抓。

- **雲端 SAM** 也是每台掛號電腦各匯入一次，寫進該 Windows 使用者的 `%LOCALAPPDATA%\nhi\cshis6\appsettings.User.json`。沒有 `C:\NHI` 可丟。`.SAM` 用隨身碟拷到那一台再匯入，不要放進 GitHub，也不必放在主機的程式根目錄。

- 病歷存檔在主機。讀卡、取號、SAM 簽章在插卡的那一台（該台的 `localhost:5066`）。工作站的讀卡、取號、SAM 與醫事人員卡簽章，必須由該台的「開啟門診.exe」開啟，才會叫到該台的讀卡軟體 6.0。用 Chrome 或 Edge 直接開主機網址，瀏覽器會丟掉這台 6.0 的回應，讀不到這台插的卡。
