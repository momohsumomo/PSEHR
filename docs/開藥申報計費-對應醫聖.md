# 開藥、計費、申報：怎麼對醫聖

問「這個藥為什麼有點數、為什麼是 0、數量為什麼不是畫面上那個」時，先讀這份，再讀 `docs/申報接手說明.md`。不要重讀醫聖全庫，也不要重讀健保 PDF。

資料在醫聖備份裡，不是另外發明的規則。2026-10-12 的備份是 `申報格式/BK1012-1.exe`（裡面的 `SC\DAT\`）。當時先解出病歷與藥品；用法表同一包裡也有，路徑 `SC\DAT\USEAGE.Dat`。

## 三個檔，各管一件事

| 檔案 | 管什麼 | 看哪個欄位 |
|---|---|---|
| `MEDICAL.Dat` | 藥品主檔。開立時的**預設** | `ISSELF` 計價註記、`CAST` 分類、`USEAGE` 預設用法、`PRICE` 主檔單價、`CODE` 健保碼、`INDEX=Y` 才是診所有在開的 |
| `HISTORY.Dat` | 那一次看診實際開的一列 | `SELFTYPE` 當次計價註記、`USEAGE` 用法、`QTY` 數量、`DAY` 天數、`PRICE` 當時單價、`MEMO` 註記符號 |
| `USEAGE.Dat` | 用法怎麼把數量變成申報總量 | `USEAGE` 代碼、`ISTOTAL` 總量算法、`FREQUENCY` 一天幾次 |

主檔是預設。寫進病歷那一列之後，**以那一列為準**。同一種藥，這次可以改成自費，下次照健保。不要用「現在的主檔」去改已經開過的病歷。

`ISSELF` 只看過三種：空白、`自`、`交`。不是 Y/1/T。

## 計價註記

醫聖畫面上的字，和病歷裡的數字，對起來是這樣：

| 畫面上 | 病歷 `SELFTYPE` | 主檔 `ISSELF` | 申報怎麼算 |
|---|---|---|---|
| （空白，健保） | `0` 或空白 | 空白 | 照單價 × 申報數量，四捨五入到整數點 |
| 自　自費或自行吸收 | `1` | `自` | 不進申報檔 |
| 交　交付檢驗（檢驗所做的） | `6` | `交` | 醫令留在檔裡，點數 0。XML 醫令類別 `p3=4`（不得計價） |
| 申　申報用、不另外給病人 | `4` | （這包病歷裡沒有對應的主檔值） | 照健保算。全庫只有 8 列，很少 |
| 轉　轉檢 | （這包病歷沒出現） | | 留在檔裡，點數 0 |
| 不　不另計價 | （這包病歷沒出現） | | 留在檔裡，點數 0 |
| 調　交付調劑時這項自調 | （這包病歷沒出現） | | 藥仍照健保算。整筆案件是否改 09，看院所開關，不看這個字 |

`SELFTYPE` 6 是交付檢驗。早期匯入誤記成「材」。影子庫裡那些列已改回「交」。程式若還看到舊的「材」，點數一樣當 0，不要再當成自費特材去加點數。

交付檢驗**不是**「凡是檢查都不計價」。主檔 `CAST=檢查` 只表示它是檢查。KOH 顯微鏡 `13017C` 也是檢查，病歷是健保，點數要算。全套血液、C 反應蛋白這類才是「交」。

主檔的「交」只負責開立時先帶上。帶上之後，註記在這一列，這一列可以改，不必回頭改藥品主檔。醫聖就是這樣：

- 血糖有兩筆。快碼 `AC` 的主檔是「交」，開過 40 次，40 次都是交。另一筆快碼「飯亟」主檔是空白，4 次裡 3 次把那一列改成交、1 次維持健保。

- 尿酸主檔是空白。16 次裡 11 次那一列是交、5 次是健保。同一筆藥，看那一次有沒有改。

- 鈉、鉀、抗鏈球菌溶血素 O、游離攝護腺特異抗原，主檔也是空白。開過的那幾次（6、6、3、2 次）那一列被改成交。

- KOH 顯微鏡主檔是空白，一千五百多次都維持健保。

所以不是漏了一個隱藏欄位。主檔沒寫「交」的，醫聖開進來也是健保；要交給檢驗所，是在那一列上改成「交」。我們一樣：選到主檔已經是「交」的（C 反應蛋白、血糖 `AC`、全套血液）會直接帶交。沒標的進來是健保，在處方那一列的計價註記改成交即可，右鍵可以選。申報看這一列。

不要再維護一份「外送檢驗代碼清單」來決定點數。那份清單跟主檔對不上，C 反應蛋白就是這樣被漏掉的。

## 用法和數量

用法代碼對 `USEAGE.Dat` 的 `ISTOTAL`、`FREQUENCY`。大小寫要照病歷上的字，`bid/pc` 和 `BID` 不是同一列。

| `ISTOTAL` | 例子 | 畫面上的數量 | 申報數量（XML `p10`） |
|---|---|---|---|
| `0` | 數量本身就是總量 | 總量 | 就是這個數量 |
| `1` 或 `2`，而且一天次數 > 0 | `BID` 一天 2 次 | 每次用量 | 數量 × 次數 × 天數 |
| `3`，而且次數是 0 | `bid/pc` | 每次用量（可以改，可以有小數） | 總量。總量不跟著數量改。沒有另外存總量就用 1 |
| `3`，而且次數 > 0 | `tid/pc`、`qd/pc` | 數量 | 不乘次數，申報這個數量 |

藥品主檔的 `CTOTALQTY` 不是一般小數，不要拿去當申報總量。`bid/pc` 用病歷上存的總量；沒存就是 1。

點數先乘完，再四捨五入成整數（.5 進位），然後各列相加。不要用程式預設的銀行家捨入。

## 單價

- 藥品：用**就醫日**落在哪一段藥價，就用那段。不拿以後公布的新價格回寫舊月份。對照在 Pack，函式 `lookup_drug_price`。

- 處置、檢查：用那一列病歷上的 `PRICE`（影子庫 `unit_price`）。主檔後來改價，不回頭改舊病歷。

- 交付檢驗：單價可以還在，申報點數是 0。

## 一個月的點數怎麼加

這段的級距、合理量、調劑費在 `src/claims/yisheng_rules.py`。這裡只記和「有沒有抓到醫聖分類」有關的結果。

2026-10-12 用當時的程式，對 115 年 5 月到 9 月醫聖已送出的申報檔，點數總額：

| | 診察費 | 藥費 | 處置費 | 調劑費 |
|---|---|---|---|---|
| 五個月 | 相同 | 相同 | 相同 | 我們較高 |

調劑費較高是因為給藥天數取最長的那一行（含外用）。這是已確認要維持的算法，不是漏抓欄位。

這是點數總額對過，不是每一筆 XML 欄位都逐格對過。還不能當成可以上傳健保局。

## 程式位置

| 要做的事 | 位置 |
|---|---|
| 病歷數字 → 畫面上的自／交 | `src/core/nhi_clinical_mappers.py` 的 `yisheng_selftype_to_pay_mark` |
| 月申報點數 | `src/claims/engine.py`：自費整列跳過；交、轉、不、舊的「材」點數為 0 |
| 數量怎麼乘 | 同檔 `_billed_quantity` |
| 開立時從主檔帶註記 | `scripts/export_yisheng_clinic_catalog.py` 讀 `ISSELF`。清單在 `frontend/public/yisheng_clinic_catalog.json` |
| 選到藥時寫進處方 | `frontend/src/utils/catalogRx.ts` |

藥品主檔有「交」或「自」、而且 `INDEX=Y` 的，開立清單裡帶這個註記。檢查只收診所自己有開的，不把整包健保檢驗灌進下拉。
